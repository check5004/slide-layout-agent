# 画像・図解生成を扱う次の課題

今回の行配置修正に画像生成機能は含めません。以下はコードで確認した現在地と、別branchで検討する要件です。

| 対象 | 持込画像 | 現在の配置 |
|---|---|---|
| 従来のPython配置8型 | `text_image` の1型 | PNG/JPEGを1枚、文章の横へfit/crop |
| 上流reference 62型 | 未対応 | image slotなし。追加画像は拒否 |
| 新作Editorial 76型 | 画像付きカードの左右2型 | `ed_cards_image_left_2` / `ed_cards_image_right_2`。画像1枚とnativeの説明2項目 |

sourceの `images` に相対パス・caption・SHAを登録し、planから `image_id` を参照します。fitは縦横比を保持して枠内へ配置、cropは枠に合わせて切り抜きます。ファイル形式・実バイト・SHA・sourceフォルダ内の参照を検証します。写真・スクリーンショットだけでなく、別途生成して保存した図解PNGもこの経路で置けます。

根拠となる実装は [Asset/TemplateImage](../slide_agent/models.py)、[asset_path](../slide_agent/io.py)、[fit/crop](../slide_agent/render.py)、[named slotへの挿入](../slide_agent/template_engine.py)、[検証](../slide_agent/validate.py) です。現在の見本画像はPillowで描いた架空UIで、AI画像生成ではありません。

未対応なのは、図解イラストの生成依頼を解釈して画像を生成する処理、生成画像の承認・差替え、複数画像や項目別画像、任意のテキスト欄を画像へ置き換えるschemaです。原文を無視した自動生成や、本文の空きを勝手に画像で埋める処理はありません。

## 別課題の実装候補

1. 画像が必要な理由と役割をplanへ記録し、対応するnamed image slotを持つlayoutを選ぶ。図文左右、2〜4項目の画像カード、横長の図解＋補足などを対象にする。既存テキストslotの意味・出典を落とす自動置換にはしない。
2. 持込画像と生成依頼を区別する。生成依頼には原文refs、描く対象、含めてよい関係、アスペクト比、背景、本文と分離するラベルを記録する。生成完了後は通常のassetとしてcaption・SHA・生成元・確認状態を残す。
3. 生成→プレビュー確認→採用した画像の固定→planへの参照→native PPTX挿入→実描画の経路を作る。失敗・未承認・不足画像は明示的に止め、原文由来の本文を削って穴埋めしない。
4. fitを標準にし、cropでは重要な対象が切れないか確認する。横長/縦長/透過PNG、画像0件・不足・過剰・壊れたファイル、差替えと出典保持をテストする。

生成サービスの選定は別途必要です。ChatGPT側の画像ツールを利用する方式と、Pythonから外部APIを呼ぶ方式を区別します。後者では認証情報、課金主体、回数・費用上限、送信してよい原文や参照画像の範囲を決めてから接続します。現在のPythonパイプラインには画像API接続や追加課金処理はありません。

## 画像とnative図形の使い分け

手順、関係図、比較軸、数値グラフ、表、本文やラベルはnativeを優先します。読み順・数値・文言を検証でき、後から編集できるためです。場面や物のイメージ、比喩的な挿絵、写真、実画面など、画像として見ることに意味がある部分をbitmapにします。生成イラストの中へ本文や重要な数値を焼き込まず、必要なラベルはPPTXの文字として別に配置する設計が候補です。
